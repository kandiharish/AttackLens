# Robustness sweep: cloud and SaaS audit logs (`robust_cloud_saas`)

Date: 1 Nov 2026. Read-only probe: no product code or config was changed.

- Fixtures: `data/raw/robust_cloud_saas/<variant>/`. There are 56 variants, each with 1 to 4 hand-written records. Values are invented (RFC 5737 IPs, example.com, fake account and tenant ids). They were generated by a scratch script, and the true UTC time of every row is in `data/raw/robust_cloud_saas/_truth.json`.
- Probe: `tools/robust/ingest_only.py`, run one variant at a time, with `--config data/out/robust_cloud_saas/_cfg`. That folder is a copy of the **live** `config/` taken at 10:02 local time, with the 512 MB / 1-thread `pipeline.yaml` from `data/snap/robust_cfg`. I used it because the default snapshot is older and does not have `azure_keyvault_json`, `azure_graph_json` or `azure_risk_json`.
- Per-row check: each row's ts, source_type, action, outcome, host, src_user, target_user, src_ip, signature, app and file_path were compared with the truth file. Results: `data/out/robust_cloud_saas/_verify.txt`.
- In-flight check: the 26 envelope variants were also run through the in-flight unpacker (`python -m attacklens.cloud_unpack`) into `data/out/robust_cloud_saas/_unpacked/`, then probed again. Results: `_verify_unpacked.txt`.

## Summary

| result | variants |
|---|---|
| PASS in the live tree | 20 |
| FAIL in the live tree, fixed by the in-flight unwrap (cyberforge-0c) once it is wired in | 21 |
| FAIL, not covered by any in-flight work (the gaps below) | 15 |

**The in-flight unwrap is not wired into the pipeline yet.**
- `cloud_unpack.raw_files()` is never called by `profile.py` or `ingest.py`. Ingest only reads the unwrap accounting file.
- So in the live tree, every `{"Records"}`, `.json.gz`, `.tar`, `.zip`, pretty JSON, JSON array, EventBridge-CloudTrail, LookupEvents, Pub/Sub and digest file is still `unrecognized`, and every physical line is counted as a drop.
- For example, the pretty `{"Records"}` file shows 133 lines dropped.
- A CloudTrail **digest** is counted as 1 dropped unrecognized row. It should be skipped with a reason.
- When the unpacker is run first, 21 of these 26 variants come out exactly right: every row, every ts, the fields, and the digest skip note.

## Notes

- User names are always cut to the local part (`carol@contoso.example.com` -> `carol`, at `ingest_sql.py:280`). This is by design, but two tenants or domains with the same local part become one entity.
- GuardDuty rows have action `other` and outcome NULL. That is by design: they are context rows only, used in alert-input mode.
- The wrong-routing in G1 also affects every non-cloud CSV whose rows start with an ISO time and contain a space. It is a profile bug, not specific to cloud logs.
- RAM was always above 1 GB free. No probe waited or crashed.
